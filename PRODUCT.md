# Product

## Platform

web

## Users

**Primary: BF6 Portal scripters.** People writing `mod` / `modlib` scripts against the Battlefield 6 Portal scripting API. They arrive mid-task — a class, a hook, or a function they need to use correctly — and they need the API answer plus whatever the community learned about it.

**Secondary: Battlefield 2042 experience creators.** Community members using Portal's rules editor (low-code, block-based) to build a game mode, looking up what a specific block takes, returns, and does. These pages are a frozen archive: they keep serving readers, but new effort does not go into them.

**Also served, by fact of the pipeline rather than by design intent:** the site's generated output is consumed programmatically — a JSON index and the block/scripting reference feed the `portal-helper` bot and browser-extension workflows. Their needs constrain structure, not presentation.

## Product Purpose

Community-written documentation for Battlefield Portal: the rules editor and its blocks, BF6's scripting API, maps, modifiers, and the tools people build around them. It exists because EA's own documentation leaves the working knowledge out, and the community was answering the same questions in Discord over and over. Success is a scripter or creator finding the answer here instead of asking, and adding what they learned back to the page.

## Positioning

The site carries what EA never writes down: how these blocks and APIs actually behave in a real mode, the workarounds, the traps, the working examples, and the "this is what nobody tells you" notes. The generated reference supplies the exhaustive substrate — every block, every map layout, the whole BF6 API surface — and the community layer supplies the judgment on top of it. A docs site that only mirrors EA's API would be a worse copy of EA's API; a commentary-only site could not be complete. Neither half is the product on its own.

## Operating Context

- Content comes from two sources that must not be confused: markdown written by contributors, and markdown generated by the `generators/` Python package (Poetry tasks `gen-docs`, `gen-docs-json`, `gen-map-layouts`, `gen-hugo-menu`) plus TypeDoc output for the BF6 scripting reference.
- For a block page, `docs/portal_blocks/<block>/docs/official.md` is regenerated from portal.battlefield.com and overwritten without warning; `extra.md` is the contributor-owned file and survives regeneration.
- Contributors work in markdown and preview with `hugo server -D`; no build tooling is required to write a page. Contribution is by pull request against `battlefield-portal-community/portal-docs` (MIT).
- The site builds with Hugo and deploys as a static site (Cloudflare Pages on `main` regenerating docs first, plus GitHub Pages workflows) to `docs.bfportal.gg`.
- Reviewers and maintainers are volunteers from the bfportal.gg Discord community; the issues they hear in Discord are the backlog.

## Capabilities and Constraints

- Sections in the navigation: Introduction, BF6 Portal (scripting: `mod`, `modlib`), Portal Builder (game modes, map layouts, rules editor), Tutorials, Tools, Contributing.
- The 2042 rules-editor block reference is the largest artifact (~270 block pages, one directory each) and is a frozen archive — maintainers fix things that are wrong but do not extend it.
- BF6 is where new documentation effort goes; its scripting reference is generated and is expected to stay current with the game version the generators target.
- Everything is static output: no accounts, no server-side rendering, no personalization.
- Constraints that are binding, not preferences: the site is not affiliated with EA or DICE; generated files are never hand-edited (the fix belongs in `extra.md` or in the generator); no analytics or tracking; MIT-licensed; content editable by anyone with a PR and nothing more than Hugo installed.
- Block illustrations are served from the community Image-CDN repository on `raw.githubusercontent.com`, not vendored into this repo. Self-hosting was evaluated and rejected in favour of repairing that upstream; a missing or 404ing illustration is an Image-CDN gap to fix there, not a reason to change the generator's image path.
- Deliberately undecided: nothing recorded here about future visual direction, new sections, or restructuring — that is design work, not product truth.

## Brand Commitments

- The name is Portal Documentation, published by the Battlefield Portal Community at docs.bfportal.gg.
- The community-only, not-affiliated-with-EA-or-DICE position is a commitment: no copy, badge, or styling may imply official status or endorsement.
- MIT license; the content is a commons, contributed by its readers.

## Evidence on Hand

- ~1,747 markdown documents under `docs/`, including ~270 generated block-reference directories with `official.md` / `extra.md` pairs.
- Working generators in `generators/` (blocks documentation, blocks JSON, map layouts, Hugo menu, Santiago/TypeDoc) — the exhaustiveness claim is backed by real pipeline output, not by hand transcription.
- Real map layout pages for the 2042 maps, real modifier/restriction/game-mode pages, real tutorials contributed by community members.
- `CONTRIBUTING.md` documenting the actual architecture and the two-file `official.md` / `extra.md` contract.
- Absent and must not be invented: any EA or DICE endorsement, official status, traffic or usage numbers, testimonials, or "thousands of creators" style claims.

## Product Principles

1. **The community's knowledge is the product.** Exhaustive generated data is the floor; the note that saves someone an afternoon is the point. When space or effort is scarce, spend it on what only practitioners know.
2. **Never launder the generated layer.** Generated pages are marked, separate, and regenerated; contributor insight lives beside them in `extra.md`, never edited into output that will be overwritten.
3. **Answer mid-task.** The reader is inside a script or a mode with a specific question. Every page should resolve that question where the reader lands, with the exact name, signature, or behavior — not a prose warm-up.
4. **BF6 gets the investment; 2042 keeps its promises.** New effort is BF6 scripting. The 2042 archive stays accurate and online, but it is not a place to grow.
5. **Low friction or no contribution.** If recording what you learned takes more than markdown and a preview server, the knowledge stays in Discord and the site dies.
